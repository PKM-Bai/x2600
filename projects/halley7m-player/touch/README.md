# 播放器 GT911 触摸输入

本模块接入 HALLEY7-M 屏幕自带的 GT911，向播放器提供逻辑横屏 `1280×720` 的单指按下、移动和释放。初始化或传输失败会释放触点，三键、播放器和显示仍可独立运行。所有 I2C 操作均由 MIPS GUI 任务发起，触摸不占用音频 PDMA，也不在中断中调用 LVGL。

## 板级连接与依据

| 信号 | 本板连接 |
|---|---|
| I2C 控制器 | I2C0，物理地址 `0x10050000` |
| SCL / SDA | PC0 / PC1，GPIO function 1 |
| RST / INT | PC8 / PC7 |
| I2C 速率 | 100kHz，按实际 APB 父时钟及分频计算时序 |
| 设备地址 | 首选 7-bit `0x14`；协议层也可识别 `0x5d` |

连接依据为本板出厂 NOR 备份中的 Linux DTB，而非 SDK 中 x16xx 的不同引脚示例。实际 DTB 的 SHA-256 为 `e34b8a451acf216b6626273ea94d0c7481a9bff637adfdb205b0679192a1b57b`，节点为 `i2c@10050000/goodix@14`，`reset-gpios` 指向 PC8、`irq-gpios` 指向 PC7，原驱动使用下降沿中断。本版使用 10ms 有界轮询，不依赖捕获短中断脉冲。

本机提取证据与脚本保留在 `build/player-touch-ui-20261021/board-evidence/`。`build/linux-display-probe-20261016.log` 记录识别到 `911_1060`，并显示复位后的 PC8 为 `in hi`。复位采用 Goodix 的地址选择与 INT 同步时序：RST 低至少 20ms，INT 高至少 1ms，RST 高至少 6ms 后恢复输入，INT 低至少 50ms 后恢复输入。每次延时额外增加一个 RTOS tick，保证从任意 tick 相位进入时仍满足最短持续时间；该时序只在初始化执行。

## 协议、方向与失败处理

GT911 协议以 [Linux v6.12 Goodix 驱动](https://github.com/torvalds/linux/blob/v6.12/drivers/input/touchscreen/goodix.c) 为依据，使用高字节在前的 16-bit 寄存器地址和 repeated START 读取，配置尺寸与触点坐标为 little-endian。

- 读取 `0x8140` 的 4-byte 产品号及 2-byte 固件版本，只接受 GT911。
- 读取 `0x8048` 起的配置尺寸与最大触点数，保留屏幕现有配置。**不上传配置表、固件或修改分辨率。**
- 只在 `0x814e` 的 READY 位有效时消费报告。先核验触点数量，再读取 `0x814f` 起的全部 8-byte 触点记录，最后将 `0x814e` 写 0。数据未读完或 ACK 失败不会发布新的按下事件。
- 首版跟踪一个手指；多指同时存在时保持原 tracking ID，避免因记录顺序变化而跳点。触点数量超限、重复 ID、坐标越界会被拒绝并释放现有指针。
- 实际配置为 `720×1280` 时，转换为 `x=raw_y, y=719-raw_x`。配置已为 `1280×720` 时直接映射。其他尺寸明确报不支持，避免以任意缩放掩盖配置问题。实板仍须检查四角及中心，确认传感器与 LCD 的实际安装方向。
- 原厂配置表的最大触点数为 10，因此协议保留最多十个记录的有界空间，不将控制器常见的五指规格误当作拒绝此配置的依据。单指时只读取一个记录；多指报告读完后仍只向 GUI 提供跟踪中的一个手指。
- 单事务传输等待上限 6ms，控制器每次 enable/disable 等待上限 1ms；超过 40-byte 的报告拆为两个连续地址读取，全部完成后才 ACK，不屏蔽中断。正常每 10ms 轮询一次，I2C 错误后退避 100ms，并释放已按下的指针，避免持续阻塞 GUI。没有触摸设备时初始化失败为非致命错误，不影响按键。

## 接口与验证

GUI 任务在界面初始化完成后调用一次 `player_touch_init()`，循环调用 `player_touch_poll(now_ms, &sample)`，并将返回的逻辑坐标与按下状态交给 GUI 指针输入。`poll` 返回 1 表示新报告、0 表示尚未就绪或未到轮询时间，负值表示错误；输出 `sample` 始终有效，错误时包含安全释放状态。init/poll 完成后以短临界区发布完整诊断副本，`player_touch_get_stats()` 只读取该副本，避免高优先级串口任务读取到更新一半的坐标。发布和读取过程均不含 I2C 事务。

播放器串口命令 `touch` 输出 `TOUCH_STATUS`，包含 ready、设备地址、产品号/版本、实际配置尺寸、旋转方式、报告/按下/释放/错误计数以及最近原始和逻辑坐标。它不触发复位、改配置或额外总线访问。

运行主机协议回归：

```powershell
python scripts/test-player-touch.py
```

也可独立构建 CMake 目标 `player_touch_test`，启用 `PLAYER_TOUCH_HOST_TESTS=ON` 后运行 CTest。主机回归使用真实协议代码和内存设备，检查两种地址、识别与配置只读、READY/先读再清顺序、释放、多指 ID 跟踪、非法计数与坐标、重复 ID、读写失败、错误退避和时间戳回绕。主机测试不代表实板 I2C、触摸方向或播放负载验收通过。
