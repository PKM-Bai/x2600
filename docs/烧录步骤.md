5. 程序验证通过后才设置精确长度的 `bootcmd`、`bootdelay=1` 并执行 `saveenv`，每次读取 256 字节，拼成完整 4KiB 环境区验证 CRC 和持久化值，再复核 SPL / U-Boot 代码与原备份相同、rootfs 与本次操作前相同。脚本最后发 `reset`，捕获正常 NOR 启动；复位启动与真正断电重启分别记录，不能混为同一验收项。

**本节是不带 `--previous` 的首装模式，要求原始启动代码 / 环境 / kernel。** 首次安装后环境和 kernel 已改变，直接重复首装会在擦除前拒绝；当前显式指定已装镜像的更新模式见本页前节，不能省略旧镜像身份或绕过核验。rootfs 允许相对历史备份发生变化，但本次操作前后必须相同。原 Linux kernel 起始内容会被应用替换，rootfs 保留不表示原 Linux 仍能直接启动。

| 区域 / 操作 | 当前范围与验证 |
|---|---|
| ReGBA 应用擦除 | `0x40000,0x120000)`，长 `0xe0000`，按原 NOR 32KiB 擦除几何对齐 |
| ReGBA 应用编程 | `[0x40000,0x11f850)`，长 `0xdf850` / 915536 字节，后至 `0x120000` 保持擦除值 |
| 环境更新 | `[0x3f000,0x40000)` 的 4KiB，通过原 U-Boot `saveenv` 对 32KiB 块读取 / 修改 / 回写；保留同块内其余原代码 |
| SPL / U-Boot 代码 | `[0,0x3f000)`，编程前后均与原始备份 CRC 核对；不是声称整个含环境的 U-Boot 分区不变 |
| rootfs | `[0x640000,0x1000000)`，记录本次操作前 CRC 并要求编程后相同，不要求等于历史备份 |

本版持久化启动命令为：

```text
sfcnor read 0x40000 0xdf850 0x80600000;go 0x80600000
```

本地编程模型覆盖固定范围、原始启动状态不符、擦除 / 编程 / 环境回读失败时停止等场景，已纳入完整主机回归。后续针对 rootfs 的修订模型另见 `build/hud-nor-flash-host-final-20261018.log`，包括已变化 rootfs 的保留以及操作后破坏的拒绝。首次预检 `build/flash-regba-nor-20261018.log` 在 rootfs 当前 CRC `8618c73f` 与历史备份 `dd62fc9b` 不同时于擦除前停止；启动代码 / 环境 / kernel 均仍匹配。当前按本次 rootfs 前后相同的规则恢复操作，见 `build/flash-regba-nor-20261018-resume.log`，应用写入和软件复位自动启动的真实结果见下一节；模型通过不代替真实断电冷启动。

实板 ID 读取使用 [probe-flash-id.py](../scripts/probe-flash-id.py)：官方 RAM SPL/helper、CPU800MHz、DDR400MHz，SFC 控制器初始化及易失性 NOR 复位后发送 JEDEC `0x9F` 读取。脚本省略 `VR_INIT`，不擦除、编程或写入 Flash 状态寄存器。USB 返回 `18 20 85`，固件整数按小端传回，解码 ID 为 `0x852018`；完整结果为 flash-id.json（本地记录 `build/flash-probe/flash-id.json`）。探测结束后需要重新复位进入 USB Boot，再进行正常烧录。

`x2600_ddr.h` 保留多个芯片的 DDR 参数用于检测，编译本板时不需要因为看到 DDR3 参数就自行删除它们。

## 3. 连接 SoC 的 USB Boot 接口

烧录需要板上连接到 X2600 USB0 OTG 的接口及支持数据传输的 USB 线。USB 转串口接口用于日志，USB Host 接口也不是 USB Boot 烧录接口。连接点应依照 HALLEY7-M-KIT 对应版本的板卡说明和丝印确认。

[君正 X2600 硬件设计指南](https://www.lumissil.com/assets/pdf/core/X2600%20Hardware%20Design%20Guide.pdf) 第 9 页的表 2.1.2 确认：`BOOT_SEL[2:0] = 011` 或 `111` 为 USB Boot；复位后 BootROM 读取这三根引脚。该指南没有提供 HALLEY7-M-KIT 的具体拨码编号，因此本说明不将二进制值换算成未知板卡的开关位置。

操作顺序：

1. 按本板硬件说明设置 USB Boot 模式，并连接 USB0 OTG 数据口。
2. 按下并释放复位键，使芯片在该模式启动。
3. 打开 Windows 设备管理器，观察此次连接或复位后新出现的 USB 设备；记录“属性 → 详细信息 → 硬件 ID”。本次已确认本板以 `USB\VID_A108&PID_EAEF` 正常识别，分类为 `libusb-win32 devices`，不会显示为COM串口。

源码中的烧录固件配置（本地依赖 `tools/cloner-source/cloner-2.5.54-src/u-boot/include/configs/burner_x2600.h:86`）定义了 **VID `A108` / PID `EAEF`**。这是 Cloner 下载到板上的烧录固件 USB ID。完整包的 INF 和 USB 平台配置均支持 VID `A108`、PID `4775 / 4780 / 4785 / 1000 / C309 / EAEF`；初次 BootROM 枚举的实际 PID 仍需接板核实。
