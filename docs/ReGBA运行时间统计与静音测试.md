# ReGBA 任务运行时间统计与静音实测

> 本文保留各阶段当时的实现与验收范围；当前工程状态见[项目 README](../projects/halley7m-regba/README.md)。`build/` 原始日志、镜像与备份，以及 `Halley7/` 原始硬件资料和本机工具包均在开发机保留，不随源码提交；精选摘要在 `docs/validation/`，其中保留的本地路径用于追溯。

日期：2026-10-16。目标是在 X2600M 主核 1.152GHz、FreeRTOS、720×1280 竖屏显示环境中，给出 `/gba_game/test4.gba` 的任务运行时间和空闲比例。音频保持静音，同时运行真实 PCM、转换和 DMA 路径，不能把这次测试描述为关闭整个音频链路后的负载。

## 实现和统计口径

`projects/halley7m-regba/include/FreeRTOSConfig.h` 启用 `configGENERATE_RUN_TIME_STATS=1`，使用 `uint64_t` 任务计数器。运行时间取自既有 `platform_time_us()` 单调微秒时钟；不重新初始化、清零 OST，也不修改原 SDK。每次任务切换由 FreeRTOS 累加当前任务的运行时间。

新增串口命令 `cpu [seconds]`，默认采样 10 秒，允许 1～300 秒。控制台先取一次 `uxTaskGetSystemState()` 快照，再用 `vTaskDelay()` 等待指定窗口，最后取第二次快照。采样期间控制台不打印统计，也不处理新命令；ReGBA、显示、音频与中断继续运行。结果在窗口结束后输出，避免把这次统计报告本身的串口忙等发送时间计入采样窗口。

两次快照按任务句柄和任务编号匹配，使用运行时间增量计算各任务比例。任务数量变化、集合变化或计数无效时返回 `-EAGAIN`，不把前后不同的任务集合拼成一张利用率表；最多支持 16 个任务。音频服务初始化前的空闲基线为 5 个任务，游戏音频运行后为 6 个任务。

| 输出字段 | 含义 |
|---|---|
| `window_us` | 实际统计窗口的板端微秒数 |
| `busy_pct` | `100% - Idle 任务时间占比` |
| `idle_pct` | Idle 任务时间占窗口的比例 |
| `accounted_pct` | 全部任务时间增量之和占窗口的比例，用于检查统计闭合程度 |
| `cpu_task runtime_us` / `cpu_pct` | 单个任务在该窗口的运行微秒数与占比 |
| `priority` | 采样结束时的任务当前优先级 |
| `stack_free_bytes` | 任务自创建以来的栈最小剩余字节数，不是这一个窗口的瞬时值 |

该口径是 FreeRTOS 任务运行时间。中断服务时间计入当时被中断的任务，包含被中断的 Idle；没有单独扣除 ISR。因此 `busy_pct` 适合比较同一固件、同一配置下的任务负载，不能据此声称已获得独立 ISR 占比或硬件性能计数器意义上的精确 CPU 利用率。LCD 和音频 DMA 自主运行时间也不会作为单独 CPU 任务出现。

## 命令和自动采样

已经运行 RAM 固件时，可以直接通过串口执行：

```text
cpu
cpu 60
```

`cpu 0`、`cpu 301` 和非数字参数返回参数错误。运行中发出 `cpu 60` 后需要等待约 60 秒，控制台才能处理下一条命令。

`scripts/profile-regba.py` 用于带屏静音复测。启动前要求核心和音频均已停止，TF 已挂载、显示已开启。脚本先发送 `audio silent` 并确认静音状态，默认加载 `/gba_game/test4.gba`，运行并预热，再获取前后状态和 60 秒任务统计。`--skip-load` 复用已经加载且停止的 ROM；复用时须由操作者确认 ROM 身份。

```powershell
.\.venv\Scripts\python.exe scripts\profile-regba.py --duration 60 --press-start
```

脚本记录原始串口日志和同名 JSON，核对实际窗口与主机时间、任务数量、各任务百分比、统计闭合率、堆栈余量、游戏/LCD/PCM/DMA 计数增长和欠载/错误计数。统计闭合率自动检查范围为 98%～102%，不要求逐项两位小数相加恰好为 100%。脚本正常结束或失败均尝试 `stop` / `audio off`，确认核心停止、音频停止且 `muted=1` 后释放串口；LCD 保留最后画面。测试不调用 `tone` 或 `audio on`，不写 NOR，也不执行 TF 写入测试。

## 实板结果

### 回归和空闲基线

本次 RAM 固件开启显示后通过 `rtos-test`：上下文 32/32 轮、抢占 102/101 次、OOM 后心跳 49、ISR 栈余量 16252 字节。随后 `core-test` 清缓存前后各运行 120 帧，耗时 2013150µs / 2013567µs，RGB555 CRC32 均为 `19b3e686`，六项 mailbox 全部符合预期，VBlank IRQ 118→238，`core-retranslate-test PASS`。自测结束 LCD 欠载为 0，音频停止且 `muted=1`。原始证据为 `build/regba-cpu-selftests-20261016.log`。

在 LCD 开启、游戏和音频均停止的状态下执行 `cpu 10`，实际窗口为 10002701µs。FreeRTOS 任务口径忙碌 0.02%、Idle 99.98%，统计闭合率 99.99%，共 5 个任务：

| 任务 | 优先级 | 窗口运行时间 | 窗口比例 | 栈最小剩余 |
|---|---:|---:|---:|---:|
| console | 3 | 1062µs | 0.01% | 12912 字节 |
| IDLE | 0 | 10001605µs | 99.98% | 1544 字节 |
| ReGBA | 3 | 0µs | 0.00% | 223672 字节 |
| Tmr Svc | 2 | 0µs | 0.00% | 2512 字节 |
| filesystem | 3 | 0µs | 0.00% | 15800 字节 |

证据为 `build/regba-cpu-idle-20261016.log`。该结果表明停止后的应用任务处于阻塞状态；LCD 中断仍存在，其时间按上述口径计入被中断任务。不能据此认定硬件实际忙碌时间只有 0.02%。

### test4.gba 带屏静音采样

已完成 `/gba_game/test4.gba` 的带屏静音实测。实际命令如下，复用了本轮已加载、已停止的 ROM；没有按 Start 或注入其他按键，测量的是默认启动流程，未认定已经进入具体关卡。

```powershell
.\.venv\Scripts\python.exe scripts\profile-regba.py --skip-load --duration 60 --log build\regba-cpu-test4-20261016.log --json build\regba-cpu-test4-20261016.json
```

10 秒预热后，CPU 统计窗口为 **60.009965 秒**，主机收到统计摘要的耗时为 60.062766 秒。FreeRTOS 任务口径忙碌 **10.79%**、空闲 **89.21%**，统计闭合率 **100.00%**，共 6 个任务：

| 任务 | 优先级 | 窗口运行时间 | 窗口比例 | 栈最小剩余 |
|---|---:|---:|---:|---:|
| ReGBA | 3 | 6443594µs | 10.73% | 160312 字节 |
| audio | 6 | 30050µs | 0.05% | 3512 字节 |
| console | 3 | 495µs | 0.00% | 12912 字节 |
| filesystem | 3 | 0µs | 0.00% | 14000 字节 |
| Tmr Svc | 2 | 0µs | 0.00% | 2512 字节 |
| IDLE | 0 | 53535861µs | 89.21% | 1544 字节 |

百分比按固件输出保留两位小数，0.00% 不代表运行时间必然为零。ReGBA 任务占比包含模拟、软件绘图、音频生成、画面缩放/缓存发布以及既有的周期性栈诊断输出；audio 任务主要处理 DMA 服务与缓冲调度。ROM 已在 RAM 中，采样中没有发起 TF 文件操作，所以 filesystem 在该窗口为零，不能用来代表加载或保存时的文件任务开销。

前后 `status` 的观测窗口为 60.138022 秒，含 CPU 报告输出前后的串口操作，因此与纯 CPU 窗口分别记录：

| 检查项 | 结果 |
|---|---|
| GBA 帧数 | 581→4173，增长 3592，平均 59.72927fps |
| LCD VBlank | 6715→8536，增长 1821，平均 30.28034Hz |
| 游戏显示提交 | 418→2238，平均 30.26372fps |
| 剩余堆 | 前后均为 26416064 字节，约 25.1923MiB |
| 核心栈最小剩余 | 160312/245760 字节，翻译深度峰值 8 |
| PCM 输入 | 427008→3079168 帧，非零输入 212630→2538433 帧 |
| 音频 DMA | 965→6979 个周期，约 100Hz |
| 静音状态 | 运行中均为 `running=1 muted=1`，DAC 静音且功放关闭 |
| 欠载与错误 | LCD 欠载、音频队列/FIFO 欠载、DMA 错误和超时均为 0 |

脚本最终打印 `CPU PROFILE PASS`，JSON 中 `pass=true`。退出后核心停在 4176 帧，`core running=0`，音频 `running=0 muted=1 queued=0`，各项欠载和错误仍为 0；显示保持开启、保留最后画面，COM52 已释放。原始串口日志为 `build/regba-cpu-test4-20261016.log`，结构化结果为 `build/regba-cpu-test4-20261016.json`。

该结果覆盖此 ROM 的默认启动流程及当前调试固件。实际操作关卡、其他 ROM、加载/保存和未来联网时需要分别采样，不能将本次 10.79% 泛化为所有游戏场景的固定占用。未执行新的 30 分钟长测、未测试声音质量，也未写入 NOR。
