> 本文保留各阶段当时的实现与验收范围；当前工程状态见[项目 README](../projects/halley7m-regba/README.md)。`build/` 原始日志、镜像与备份，以及 `Halley7/` 原始硬件资料和本机工具包均在开发机保留，不随源码提交；精选摘要在 `docs/validation/`，其中保留的本地路径用于追溯。

更新日期：2026-10-16。**阶段 5 的基础显示移植及本轮板上验收通过**：已按原 Linux 的 `zc50289hshd02` 驱动参数接入现有竖屏，用户确认静态彩条及真实游戏画面正常，显示开启后的核心自测与清缓存重译通过。第三版完成 320 秒静音游戏/显示/音频/TF 联合短测；第四版修正显示重开的 PHY 状态后，连续两轮关闭/重开及用户视觉确认通过，并另行完成 60 秒真实 ROM 显示/静音音频回归。Release/Debug 构建和产物校验通过，全程只加载到 RAM。本轮不包括反复断电冷启动、全游戏兼容性或显示版本 30 分钟压力。

本阶段保持 720×1280 原生竖屏，不旋转画面；GBA 游戏显示为居中的 720×480 区域。只通过原 U-Boot 加载到 RAM，不写 NOR。音频保持 `audio off` 或 `audio silent`，本阶段不播放测试音。

## 实际硬件基线

原 Linux 为 5.10.186+。`/sys/bus/platform/drivers/zc50289hshd02` 实际绑定 `display-dbi:panel_zc50289hshd02`，`fw050` 驱动目录没有绑定设备。因此，本次按 **ZC50289HSHD02 对应驱动**的初始化命令和时序实施。用户提供的屏幕标称为“TFT FW050”，实物背标、排线丝印及厂家对应关系尚未核实；软件绑定不足以将实物型号确定为 ZC50289HSHD02，也不能据此排除 FW050。

| 项目 | 原 Linux 实际依据 |
|---|---|
| fb0 | `layer0`，模式 `U:720x1280p-30`，32bpp，stride 2880 字节，虚拟分辨率 720×2560 |
| 帧缓冲 | 两帧，共 7372800 字节 |
| MIPI | 2 lane、RGB888、burst；lane2/3 PN swap 配置保留原板设置 |
| 水平时序 | HBP 100、HFP 100、HSYNC 10 像素 |
| 垂直时序 | VBP 30、VFP 20、VSYNC 2 行 |
| LCD 时钟 | MPLL 1.8GHz，LCD 分频字段 47，实际为 37.5MHz；`LPCDR=0x4000002f` |
| 面板名义像素时钟 | 37162800Hz；用于 SDK 的 DSI 时序计算，byte clock 为 83616kHz |
| 供电与复位 | PC11 低电平使能供电，PC10 复位；原 Linux 稳态分别为低、高 |
| 背光 | PC14 / PWM15；原始 `PWMCDR=0x00000002`、通道 CC15=`0x00000005`、WC15=`0xa6aa5356` |

背光首版复用原 Linux 的原始寄存器配置。Linux 请求的 PWM 周期为 1000000ns、占空时间为 666666ns，但本轮没有示波器测量，不将其表述为已实测 1kHz。

PHY 的模拟参数和五组 lane 时序已从正常工作的 Linux 读取，供派生驱动使用。证据：

- `build/linux-display-probe-20261016.log`：启动、实际 panel 绑定、fb0、时钟和 GPIO。
- `build/linux-display-registers-20261016.log`：DSI PHY 与 PWM 原始寄存器读取。

原系统 sysfs 的 DSI 调试查询会触发部分重新配置，不能将所有 sysfs 调试入口视为纯读取；后续参考的是正常显示状态下的寄存器读取结果。用户随后确认原画面正常。

## 软件实现

代码位于 `projects/halley7m-regba`。显示不在启动时自动开启；核心停止后，通过 `lcd on`、`lcd test`、`lcd off` 请求，由核心任务串行执行显示操作。新增 `lcd diag` 只读输出控制器状态和帧缓冲像素，`lcd vpg` 可选择内部彩条用于定位链路；本轮尚未实际执行 `lcd vpg`，不计为通过项。`status` 增加 `lcd active`、`vblank`、`presented`、`skipped`、`underrun`、缩放耗时与帧缓冲分配量。

| 文件或入口 | 当前职责 |
|---|---|
| `platform/panel_zc502.c` | ZC502 初始化命令、PC11 供电、PC10 复位、PC14/PWM15 背光及面板时序 |
| `platform/video.c` | LCD/DSI 时钟、SRDMA、动态双缓冲、轻量中断、画面提交、测试图和停止释放 |
| `platform/video_blit.c` | 240×160 GBA 像素转换为 XRGB8888，3 倍最近邻缩放到 `(0,400)`，只写 720×480 游戏区域 |
| `core/regba_core.c` | 从 `ReGBA_RenderScreen()` 提交完整客体帧，保持现有 GBA 帧率与核心 CRC 路径 |
| `scripts/prepare-display.py` | 在构建目录派生三个 SDK 显示源文件，并记录输入和产物哈希；不改写 SDK 源码 |

ReGBA 的 16 位输入使用 R 位 0～4、G 位 5～9、B 位 10～14，忽略第 15 位；输出为 `0xFFRRGGBB`。显示区域为 x=0～719、y=400～879，上下各保留 400 行黑边。保持竖屏方向，不拉伸为满屏。

两个 720×1280×4 字节帧缓冲按 64 字节对齐动态分配，图像数据共 7372800 字节，另有对齐余量。分配在显示开启时进行；`lcd off` 确认 DMA 停止后才释放。实板保持显示开启，从 TF 成功载入 33554432 字节 ROM 后，剩余堆为 7257240 字节，证据为 `build/regba-display-game-load-20261016.log`；音频任务创建后联合短测的稳态剩余堆为 7251960 字节。

面板约 30Hz，GBA 维持约 59.7275 帧/秒。核心提交采用非阻塞策略：无空闲后缓冲时跳过本次显示提交，继续模拟。回收旧前缓冲须同时满足后续显示完成中断到达、SRDMA 读地址落入新帧缓冲范围，避免仅凭提交函数返回就覆盖仍在读取的图像。本轮真实游戏中用户未观察到明显撕裂，短测的显示提交及模拟帧率见后文。

显示中断只统计 EOD/UOT 并清除标志，不输出串口、不调用 RTOS、不使用 HAL 自旋锁。帧缓冲内容和 RDMA 描述符在交给 DMA 前显式发布缓存。派生 SDK 修订包括 DSI 静态对象、保留有符号命令错误、初始化后的 PHY 地址日志、MIPS 缓存发布、原 Linux PHY 配置，以及 DSI video 参数修改前先关闭输出。TFT `sync_dl=0` 与原系统一致。

## 已完成的软件验证

`scripts/test-regba-host.ps1` 使用 MSVC `/WX` 构建并实际通过原存储回归、140 组音频转换组合及新增像素转换回归。证据为 `build/regba-host-display-20261016.log`。

像素回归直接编译生产 `video_blit.c`，使用独立字面颜色期望和目标坐标反向映射进行比较。源 stride 为 256 像素、目标 stride 为 736 像素，覆盖 RGB、灰度、中间色、bit15 忽略、四角及非对称图案、全部 3× 像素、上下边框、行尾 padding 和分配区两侧保护字。两轮分别翻转 bit15；每轮检查全部 942208 个目标字及 41088 个源字，未改写输入或游戏区域外的目标数据。

该主机检查不访问真实 LCD、TF、USB 或 NOR，也不覆盖 MIPS 缓存、SRDMA、中断、PHY 或实际颜色顺序。

## FreeRTOS 实板修订与验证

### 第一版：初始化推进但没有画面

首版显示固件 Release 为 730816 字节，静态布局后初始堆 48480256 字节；Debug 为 1364672 字节、初始堆 47845376 字节。Release 经原 U-Boot 加载到 RAM，长度及板端 CRC 校验通过后启动，未写 NOR。载入日志为 `build/ramload-display-20261016.log`，BIN SHA256 为 `d4cb5d2d641fdcd7de8759b21f9b2e4315344e9ab8817fff3cfcf474c7b1dc92`，板端 CRC32 为 `c23dece8`。

`lcd test` 的初始化返回成功，`vblank` 持续按约 30Hz 增长、`underrun=0`。用户实际观察为背光亮、屏幕完全黑色，未显示彩条或边框，因此首轮静态图验收失败。显示完成计数说明控制器仍在推进，不能证明面板收到有效图像或提交的帧缓冲已实际显示。

### 第二版：诊断确认帧缓冲内容与读地址

第二版将 TFT 同步配置匹配为原系统的 `sync_dl=0`，并在派生 `jz_dsi_video_cfg()` 中将参数配置前的 DSI power 从 1 改为 0，使参数在停止输出时更新。用户仍然观察到黑屏，未将这两项修订单独视为画面问题已解决。

`lcd diag` 读取显示中的第二个缓冲区：边框像素为 `ffffffff`、彩条采样为 `ffffff00`，SRDMA `SITE` 位于该缓冲范围内；DSI 错误寄存器为 0，`underrun=0`。这将定位重点进一步收窄到面板初始化顺序和链路，但这些寄存器证据仍不能替代实际可见画面。日志为 `build/regba-display-second-20261016.log`。

### 第三版：补足复位等待，静态图通过

原 U-Boot 在面板复位后再初始化 PHY，形成至少约 25ms 的间接等待；当前 HAL 先初始化 PHY，再执行面板复位，原先的间接等待随调用顺序变化而消失。第三版在面板复位释放后明确等待 120ms，再发送初始化命令。202 条初始化命令已与 NOR 备份中原内核偏移 `0xC1A270` 的表逐条比对，202/202 一致。

第三版 Release BIN 为 731840 字节，初始堆 48480256 字节；Debug BIN 为 1366080 字节、初始堆 47845376 字节，编译和产物验证通过。Release SHA256 为 `0e3b79d696b7508b77ed0b41367f838b0da0a1404a0b9d2a44cc39904c0d8d73`，RAM 加载 CRC32 为 `dfd54f2d`，日志为 `build/ramload-display-third-20261016.log`。仍只在 RAM 运行，未写 NOR。

用户实际确认第三版彩条全部正常、没有异常，静态图验收通过。该项独立检查验证初始化顺序下的静态画面；动态游戏及联合负载另按后续实际结果记录，不能由彩条正常直接推定。

### 显示开启后的核心自测

第三版保持显示开启执行 `core-test`：先运行 120 帧，再清空 JIT 缓存，从同一客体状态续跑 120 帧。两轮均通过 ARM/Thumb/SWI/IRQ/RAM-code/SMC 和完整源帧像素检查，mailbox 全部符合期望；耗时分别为 2012980µs 和 2013287µs，RGB555 CRC32 均为 `19b3e686`，IRQ 计数从 118 增至 238，`core-retranslate-test PASS`。

随后状态为 `presented=123 skipped=118 underrun=0`，最后一次缩放/缓存发布耗时 977µs、最大 13957µs；最大值包含首次清除整帧静态测试图背景的开销。该样本说明显示提交可跳过客体帧而继续模拟，尚不替代真实游戏长时间帧率统计。证据为 `build/regba-display-coretest-20261016.log`。

### 真实 ROM 可见画面

显示开启时从 TF 成功载入已校验的 `/gba_game/test1.gba`，共 33554432 字节。用户确认真实游戏画面正常，没有明显闪烁、花屏或撕裂，上下黑边布局正确。这是本块开发板、本块屏幕和当前这一份 ROM 的动态画面观察结果，不扩展为所有游戏兼容性或长时间稳定性通过。

### 320 秒显示/静音音频/TF 联合短测

第三版使用 `scripts/soak-regba.py --skip-load --duration 320 --press-start --require-display` 实际完成联合短测，退出码 0，打印 `SOAK short-run PASS: actual=320.133s; requested=320s`。`--require-display` 在原有游戏、PCM/DMA、时钟和文件检查基础上，要求 LCD 活跃、缓冲分配为 7372800 字节、显示完成及提交计数持续增长、LCD 欠载为 0。全程使用 `audio silent`、`muted=1`，未播放测试音。

### 第四版生命周期修订与复核

定位到前一轮的 HS clock request 未清除。第四版在停止 DMA 后、关闭门控前，以及再次开启门控后、HAL 初始化前，清零 DSI `LPCLK_CTRL`、`PWR_UP` 和 `PHY_RSTZ`。Release 为 731840 字节、初始堆 48480256 字节，Debug 为 1366176 字节、初始堆 47845376 字节，构建和产物验证通过。

第四版 Release SHA256 为 `8f6b26a5c3f2412d2155cf8427f8544e6690f5f297a179a628ead07ea2df1152`，RAM 加载 CRC32 为 `1cdc106f`，经原 U-Boot 校验后从 RAM 启动，日志为 `build/ramload-display-fourth-20261016.log`。第三版 320 秒联合短测结果保留为第三版证据，不合并为第四版已完成同长度压力。

第四版实测首次开启及连续两轮 `off` / `on`，所有开启均返回 `lcd result=0`，未再出现 PHY 警告，`underrun=0`。每次开启后堆为 40814176 字节、`allocated=7372800`，关闭后堆为 48187048 字节、`allocated=0`，释放量均为 7372872 字节，没有出现逐轮内存减少。用户确认两轮重开后的彩条正常、无明显异常，生命周期验收通过。日志为 `build/regba-display-fourth-lifecycle-20261016.log`。

### 第四版真实 ROM 60 秒回归

完成显示开关复核后，再次从 TF 载入同一份 33554432 字节 ROM，加载成功，剩余堆为 7257240 字节，日志为 `build/regba-display-fourth-load-20261016.log`。随后显示开启、`audio silent`，实际执行 60 秒回归，主机退出码 0，打印 `SOAK short-run PASS: actual=60.161s; requested=60s`。

运行样本板端 `time_us` 从 234309512 增至 294468536，跨度 60.159024 秒；GBA 帧 293→3886，约 59.72504 帧/秒；LCD 完成计数 5311→7133，提交计数 150→1971，分别约 30.28640 和 30.26977 次/秒。两次运行样本的剩余堆均为 7251960 字节，核心栈最小余量均为 160312/245760 字节；LCD 欠载及音频队列欠载、FIFO 欠载、错误、超时全部为 0。该 60 秒回归覆盖第四版实际游戏/显示/静音 PCM/DMA，没有在其中另做一次 TF 写读；并行 TF 写读证据属于第三版 320 秒联合短测。

结束后核心正常停在 3890 帧，`audio_requested=0`，音频 `running=0 queued=0 muted=1`；LCD 保持开启，`vblank=7165 presented=1973 skipped=1918 underrun=0 allocated=7372800`，屏幕保留最后一帧。COM52 已释放，未写 NOR。原始日志为 `build/regba-display-fourth-regression-20261016-60s.log`，统计结果为 `build/regba-display-fourth-summary-20261016.json`。
