更新日期：2026-10-16。本轮已在现有 FreeRTOS / ReGBA 工程接入底板三枚独立用户键，映射为 Start、A、B；显示继续使用 720×1280 原生竖屏。Release / Debug 构建及产物检查、包含生产消抖实现的主机回归均已通过。`test4.gba` 实板测试中，用户确认三枚键都有响应，串口同时记录各键的按下和释放；物理长按、组合键及两路输入合并仍待逐项验证。

## 实际按键与映射

依据本地 HALLEY7 底板原理图（本地资料 `Halley7/01_BASEBOARD/01_SCH/RD_X2600_HALLEY7_BASEBOARD_V1.0.pdf`） 第 5 页，三枚用户键均有外部 10kΩ 电阻上拉至 1V8P，按下时接地，低电平有效。

| 底板丝印 | SoC 引脚 | 映射 | GBA 掩码 | 外围 |
|---|---|---|---|---|
| SW6 | PE13 | Start | `0x008` | R199，10kΩ 上拉；C163，0.1µF |
| SW3 | PE14 | A | `0x001` | R97，10kΩ 上拉；C128，0.1µF |
| SW4 | PE15 | B | `0x002` | R98，10kΩ 上拉；C129，0.1µF |

三枚键已在底板上连接，无需外加跳线。启动选择和复位另有专用按键：SW1 为 USB Boot / PD15，SW5 为 eMMC Boot / PD16，SW2 为 RESET，不纳入本次游戏键映射。按游戏键时使用 SW6、SW3、SW4 的板上丝印区分。

PE13～PE15 与当前 TF 的 PB0～PB3、LCD 的 PC10/PC11/PC14、功放 PE17 分开，不占用保留给 Wi-Fi 的 MSC1 / PC25～PC30。

## 输入实现

按键使用独立 FreeRTOS 任务扫描，优先级 4，栈 768 words / 3KiB；每 5ms 采样一次，状态连续稳定 20ms 后才提交。GPIO 配置为输入，保留外部上拉，关闭内部上拉和下拉。

GPIO 逐引脚调用 `setPinMode()`，避开 SDK `setPinMaskMode()` 在当前 MIPS 配置下受 `RISCV_ON` 条件编译影响的问题；SDK 原文件不修改。

消抖同时适用于按下和释放。长按保持对应 GBA 位，不按扫描次数重复产生边沿；两个或三个键可同时按下，掩码按位或合并。持续时间短于消抖窗口的电平变化不提交给游戏。

有效输入由两路组成：

```text
游戏按键掩码 = 串口 keys 掩码 | 板载消抖稳定掩码
```

串口 `keys 0` 只清除串口输入，正在按住的板载键仍然有效。板载键松开后清除其自身输入位；如果同一位仍由串口保持，游戏继续收到该位，直至两路均释放。

## 调试入口与使用

`buttons` 用于读取板载按键诊断信息；`status` 同时输出按键状态，核心状态区分有效 `keys`、`serial_keys` 和 `board_keys`。按键诊断格式为：

```text
BUTTONS running=1 raw=000 stable=000 debounce_ms=20 sample_ms=5 Start_PE13=0/0 A_PE14=0/0 B_PE15=0/0 (press/release)
```

`raw` 是即时采样转换后的 GBA 按键掩码，`stable` 为消抖后的掩码；二者均使用 1 表示按下，已将 GPIO 的低有效电平转换为游戏语义。每键的两个计数依次为按下次数 / 释放次数。上述示例表示三键均释放，实际计数按当前启动后的操作累计。

典型检查顺序：

1. 启动后不按键，执行 `buttons`，确认三键均释放、板载稳定掩码为 0。
2. 单独按住 SW6、SW3、SW4，分别确认稳定掩码为 `008`、`001`、`002`；松开后恢复 0。
3. 长按每键后复查计数，确认一次长按只有一次按下边沿，释放只增加一次释放计数。
4. 同按 SW3＋SW4，确认 `003`；三键同按为 `00b`，逐键松开后按剩余键更新。
5. 物理键保持时执行 `keys 0`，确认板载输入仍有效；串口与板载分别释放时，核对合并规则。
6. 加载 `/gba_game/test4.gba` 并保持静音，观察 Start 进入流程以及 A/B 在游戏中的实际操作。

本轮只提供三个输入，方向键、Select、L、R 尚未接入；这些位仍可通过既有串口 `keys` 命令设置。游戏内需要方向选择的菜单和操作暂不能完全通过三枚板载键完成。

## 验收记录

Release / Debug 均已实际构建，并通过 `scripts/verify-regba.py` 的 ELF 入口、ABI、未解析符号、内存布局与堆预算检查：

|---|---:|---:|
| Release | 736240 | 48472064 字节 |
| Debug | 1373408 | 47837184 字节 |

构建日志为 `build/buttons-Release-build.log`、`build/buttons-Debug-build.log`。Release BIN 的 SHA256 为 `e897ff55a43a17f155317c94f6ce11617fe8f0f8d0c56288c73db3d5b1485c0c`，入口仍为 `0x80600000`。

主机入口 `scripts/test-regba-host.ps1` 已通过存储、音频、像素转换原有回归及新增 `tests/buttons_test.c`。按键测试直接编译生产 `platform/buttons.c` 的同一消抖状态机，覆盖短毛刺、19ms/20ms 边界、长按不重复、释放抖动、三键组合、各键独立消抖、32 位计时回绕和无关位过滤。这些检查只操作主机 RAM，不访问 GPIO，也不替代板载电气、扫描调度、输入合并和游戏操作验收。

Release 已通过原 U-Boot / YMODEM 加载到 RAM，736240 字节、板端 CRC32 `6bb7d7a2` 与主机一致；SHA256 与上述 manifest 相符，校验后从 `0x80600000` 执行。载入日志为 `build/ramload-buttons-20261016.log`，未写 NOR。

启动日志 `build/regba-buttons-boot-20261016.log` 中，`buttons task=0` 表示扫描任务创建成功；初始 `BUTTONS running=1 raw=000 stable=000`，三键按下/释放计数均为 `0/0`。该状态证明当前空闲输入未误报按下，尚不证明物理按键已经接通。启动时剩余堆为 48175584 字节、任务数 6，音频 `running=0 muted=1`；随后 LCD 开启、TF / FAT32 挂载均成功。

### 真实游戏中的三键操作

`build/regba-buttons-load-20261016.log` 记录 `/gba_game/test4.gba` 载入成功，共 14385152 字节。游戏连续运行，显示沿用居中的 720×480 区域；音频使用 `audio silent`，PCM / DMA 继续工作但 DAC 静音、扬声器关闭。

日志为 `build/regba-buttons-running-20261016.log`、`build/regba-buttons-verified-20261016.log`。计数在用户操作期间累计；未同步记录每键实际按压次数，不据此认定每次物理按压只有一次边沿，消抖物理效果仍待专门验证。操作后 `raw`、`stable` 及核心的有效、串口、板载掩码全部为 `000`，各键按下/释放计数相等；结合用户确认，三键的基本映射与松开回零通过。

操作后 LCD `underrun=0`。音频保持 `running=1 muted=1`，DMA 完成 12494 次；`queue_under=1`、`FIFO_under=1`、`errors=0`、`timeouts=0`。本次出现了各一次队列和 FIFO 欠载，因此不将该轮写成音频无欠载通过；现有计数无法单独确定欠载发生时刻或是否与按键扫描有关。本轮按键功能结论与音频连续性结果分别记录。

### 新增扫描任务的运行开销

本轮另行执行 `cpu 10`，日志为 `build/regba-buttons-cpu-20261016.log`，窗口为 10001678µs。主核忙碌 11.82%、空闲 88.18%；ReGBA 为 11.72%、audio 为 0.04%。按键任务运行 2706µs，报告显示 0.02%，按任务累计时长和窗口计算约为 0.027%；任务栈最小剩余 2504 / 3072 字节，核心栈最小剩余 160312 字节。

该占比对应当次游戏状态及窗口，不把与此前默认启动流程的差异全部归因于按键任务。任务统计仍沿用 FreeRTOS 口径，中断时间归入被中断任务。
