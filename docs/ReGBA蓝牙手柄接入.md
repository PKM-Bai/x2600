# ReGBA 蓝牙手柄接入

> 本文保留各阶段当时的实现与验收范围；当前工程状态见[项目 README](../projects/halley7m-regba/README.md)。`build/` 原始日志、镜像与备份，以及 `Halley7/` 原始硬件资料和本机工具包均在开发机保留，不随源码提交；精选摘要在 `docs/validation/`，其中保留的本地路径用于追溯。

本轮为 HALLEY7-M / X2600M 的 FreeRTOS ReGBA 接入塔克 SBTCOM1 蓝牙串口接收器与 X3S / G6S 手柄。X2600 接收模块已经整理的 TTL UART 数据，无需在 FreeRTOS 中增加蓝牙协议栈。最终主路线为 **UART2 RX / PD12 FUNCTION0 / J10 pin2** → X-Protocol 解析 → GBA 按键掩码，并与板载键、串口 `keys` 输入按位或合并；供电与地保留在 J3。

## 硬件接线与配对

断电后按下表接线。本次只移动橙线，红 / 棕线和 TF 原线不动。用户已确认 J3、J10 都有焊好的公针，J10 没有 WiFi 子板；针脚号以原理图及实板 pin1 标识为准。

| SBTCOM1 引脚 | Halley7 底板引脚 | 信号 |
|---|---|---|
| TXD（橙） | **J10 pin2** | PD12，FUNCTION0 = UART2_RXD |
| VCC（红） | **J3 pin14** | 经 R42=0Ω 接 3V3P |
| GND（棕） | **J3 pin10** | GND |
| RXD | 不接 | 当前接收路径无需发送 |

本地底板 BOM 的 `PCBA BOM` 工作表 C48:F48 明确 J10 为 `HEADER13X2_2D0`、`HEADER 13X2 2MM MALE`，即 **2.00mm、13×2 共 26 针公排针**；C44:F44 明确 J3 为 **2.00mm、7×2 带护套公座**，通用型号 `CON14AP`。来源为 `Halley7/01_BASEBOARD/00_BOM/RD_X2600_HALLEY7_BASEBOARD_V1.0_COMPONENTS LIST.xlsx`，未给具体制造商订货料号；连接母头须能夹紧相应公针。

底板原理图 `Halley7/01_BASEBOARD/01_SCH/RD_X2600_HALLEY7_BASEBOARD_V1.0.pdf` 第 5 页确认 J10 pin2 为 UART2_RXD / PD12，第 6 页确认 J3 供电 / 地。核心板第 4 页标 PD12 为 **3.3V_PU**，PM GPIO 表确认 function0；底板该网仅连接核心接口 U5 pin137 与 J10 pin2，没有 RTC 或 MIPI 触摸支路。TF 的 PB0～PB3、现用 VCC J10 pin12 / GND J9 pin6，以及调试 UART0 均不改动。

**本接法与 J10 WiFi 子板互斥。** 参考 WiFi 子板 J1 pin2 接 `WL_WAKE_HOST` 输出，装回后会与 PD12 共网；使用 SBTCOM1 UART2 时必须保持子板拔除。未来装回 WiFi 前须先断开该 TXD 连线、重新安排串口，不能同时插用。

模块手册说明支持 3.3V 或 5V 供电，本接法使用 3.3V。资料没有给出 TXD 高低电平的明确电气规格；不能把“支持 5V 供电”理解为 X2600 的 RX 可接收 5V。本轮尚未测量接收器 TXD 电压。

串口固定为 **115200、8N1、无硬件流控**。调试控制台仍使用开发板原 UART0 串口。

配对步骤依据本地 SBTCOM1 手册第 6～9 页：

1. 模块上电后确认处于主机模式，蓝灯闪烁表示搜索，蓝灯常亮表示连接成功。需要切换模式时，长按模块按键超过 3 秒，等两灯同时亮起后松手。
2. 首次绑定或更换手柄时，先关闭原来绑定的设备，在模块主机模式下短按按键，进入绿灯常亮、蓝灯闪烁的搜索新设备状态。
3. X3S 按住 **X** 再按 **HOME** 开机，进入安卓标准蓝牙 HID 模式；红色 LED4 由闪烁变为常亮表示已连接。G6S 先将背面拨到 **V3**，再按住 **X** 并按 **HOME**；HOME 黄灯由闪烁变常亮表示已连接。
4. 模块蓝灯常亮后执行 `btpad`，再按下并释放一个按键，确认完整手柄数据帧计数增长。LED 连接成功不等于已验证 UART 和按键映射。

模块只绑定一台当前设备；绑定后断电重启会搜索该设备。手柄休眠会断开，重新开机后检查连接和输入恢复。

## 协议、输入映射与执行方式

只接收 X-Protocol 的 `0xA0` 手柄帧：`AA 55` 帧头、整帧长度、帧号、类型、载荷、8 位累加和。标准数据类型为 `0x01`，载荷含左右摇杆、方向键、按键位与左右扳机；连接类型为 `0x00`，`0x55` 表示连接、`0xFF` 表示断开。长度与校验未通过的帧不更新输入，其他设备 / 类型帧不作为手柄数据使用。

| 手柄操作 | GBA 输入 |
|---|---|
| 十字方向键 | 上 / 下 / 左 / 右；当前实物右上输出受限 |
| 左摇杆 | 上 / 下 / 左 / 右及斜向；右上已实测通过 |
| A / B | A / B |
| LB / RB | L / R |
| SELECT / START | Select / Start |
| Y | GUI 版菜单入口，不作为 GBA 按键；前版已有 `key2=0x10` 后暂停 / 恢复及切换日志。最终版通过串口驱动 GUI 完成 32MiB 切换 / 保存 / 退出，未重做物理 Y 验收 |
| X、LT / RT、L3 / R3、右摇杆 | 暂不映射 |

左摇杆绝对值达到 48 时进入方向，回落到 32 或以下时释放，支持斜向组合；十字键非中立时优先于左摇杆。UART6 首轮已确认 `BT_GAMEPAD_X_RIGHT_SIGN=1`、`BT_GAMEPAD_Y_UP_SIGN=1`，四方向为 010 / 040 / 020 / 080，摇杆右上为 050，释放归零，`axis_verified=1` 已同步。解析器支持十字枚举 2 / 4 / 6 / 8 的斜向；但本实物在持续 A 帧下同时压上右时，原始 dpad=0、其他方向字段中立、A 仍为 1，单上为 1、单右为 3，已定位为当前手柄 / 模块输出层的十字右上限制，不通过修改解析器生成不存在的输入。左摇杆右上已验证，可用于斜向操作。

UART2 使用接收中断，每次中断最多处理 64 字节，不建立独立轮询任务或 DMA 通道；中断内不打印日志。数据在现有输入获取路径合并，`btpad` 只在控制台任务打印诊断。显式断开提示帧与 UART 错误会清除蓝牙按键状态；连接提示本身不恢复之前按住的键，须等待新的标准数据。

初始化设 PD12 为 FUNCTION0，并仅对 PD12 写 `PxPUS` / `PxPDC`，启用上拉并关闭下拉。原 SDK `LL_GPIO_setPinPull()` 的物理地址 / MIPS KSEG1 比较会使该调用无操作，因此沿用模块内单引脚配置方式，不改 SDK 或其他引脚。此前 PC1 / PB22 的电平实测不能代替 PD12 板测。

`BT_GAMEPAD_TIMEOUT_MS` 当前为 **0**，即关闭静默超时清键。本轮已实测 64.859 秒静置没有新增数据帧，虽然 A 连续长按 112.406 秒期间最大数据年龄仅 31ms，静置上报门槛仍不满足，不能启用 500ms 超时。按住关机发送断开提示后的清键已验证；接收器直接掉电、完全静默且没有断开提示时，仍可能保留最后一次蓝牙按键，该情形尚未实测。

仅当“静置 60 秒”和“持续长按 60 秒”两段实测均有完整数据持续更新，且各段 **`max_gap_ms <= 100`**，才将超时改为 **500ms** 并重新构建和验收。未达门槛则保持 0，不把掉电自动清键记为通过。主机回归需同时覆盖 timeout=0 和 timeout=500 两种配置；主机测试不构成发送周期的实物证据。

## 诊断与首轮实测步骤

UART2 固件启动时预期报告 `btpad init=0`、UART2 RX=PD12、J10 pin2、115200 8N1；非零表示初始化失败。`btpad` 和完整 `status` 将输出蓝牙状态与累计计数，重点记录：

- `initialized`、`connected`、`data_valid`、`keys`，以及 `timeout_ms`、`x_right_sign`、`y_up_sign` 和 `axis_verified`。当前最终固件打印两轴 sign=1、`axis_verified=1`。
- 原始左右轴、`dpad`、`key2`、`key3`、`rtrig`、`ltrig`，用于核对方向和按钮。
- `bytes`、`data_frames`、`link_frames`、`checksum_errors`、`length_errors`、`ignored_frames`、`resyncs`、`uart_errors`。
- `last_gap_ms`、`max_gap_ms`、`data_age_ms`、`stale`，用于判断完整手柄数据的间隔及超时行为。`connected` 是协议观测值，不能单独证明无线链路仍在线。
- `btpad_hw`：IRQ 次数、接收中断保存的 `last_lsr` / `last_error`、PD12 的电平 / 复用 / 上下拉，以及 UART2 的 IER / LCR / MCR / UMR / UACR、时钟门控与 INTC 屏蔽状态；PD12 预期 `mode=00`。控制台只读取不破坏现场的寄存器，不直接读取会清除错误 / 中断证据的 UART ULSR / UIIR。

本轮音频专项调试已按用户要求停止，`main.c`、`platform/audio.c`、`platform/audio.h` 中新增的诊断、可调增益和 PCM 抓取接口已撤除，192000 字节抓取缓冲、抓取脚本及临时音频辅助脚本已删除。正常游戏音频恢复原默认增益 **200（−13dB）**；已有 `audio on` / `silent` / `off` 与运行计数保留。下文的音频调试对照仅为历史记录，`btpad` 继续用于蓝牙接入诊断。

首轮由用户操作手柄，调试端保存完整串口日志。进入游戏前先完成下列步骤：

1. 先整板断电，确认 J10 无 WiFi 子板，将橙 TXD 从 J3 pin3 移到 J10 pin2，红 / 棕 / TF 原线不动。随后按 RAM 流程校验 UART2 固件长度 / CRC 并启动，记录最初的 `btpad` 基线，再分步配对、收帧、开屏和加载游戏，每步检查错误增量。保持音频关闭或 `audio silent`，不播放 `tone`。
2. 完成上述配对，确认完整数据帧计数增长；若收到连接提示，`link_frames` 也应增长。模块在固件启动前已经连接时，不要求重发连接提示，新的合法数据帧也可建立输入状态。分别按住并松开十字键上、下、左、右，再操作左摇杆四方向与斜向。每次操作时记录原始轴、`dpad` 与 `keys`；松开后蓝牙掩码应回零。核对 X / Y 极性后才能把方向映射记为通过。
3. 分别验证 A、B、LB、RB、SELECT、START 的按下、持续按住和释放，再验证 A+方向、A+B 等组合。确认不映射的按钮不会生成 GBA 按键。分别合并板载键和串口 `keys`，松开蓝牙键时其他来源的按住状态仍应保留；最后执行 `keys 0`。
4. 从一次新启动 / 已知统计起点开始，手柄静置 **60 秒**，每秒抓取一次 `btpad`，保存开始与结束的累计数据帧数和 `max_gap_ms`。再从独立统计起点持续按住一个方向或 A **60 秒**，同样抓取日志并确认掩码始终保持。统计为累计值时用重新启动分隔两段；两段均须取得 `max_gap_ms <= 100` 的实际记录，才能启用 500ms 超时。
5. 在按住按键时正常关闭手柄或让手柄断开，观察 `0xFF` 断开提示、连接计数和清键。重新开机连接，确认新的数据可恢复输入，之前按住的键不会因连接提示自行恢复。
6. 在按住按键时切断接收器供电，记录是否收到断开提示及最终掩码。timeout=0 时无提示的静默不保证清键；该观察不可写作掉电保护通过。满足周期门槛并改为 timeout=500 后，重复静置、长按、手柄断开、接收器掉电和重连；静默后应在 500ms 超时及下一次输入读取时清除蓝牙键，正常静置 / 长按不得误触发 `stale`。

计数出现校验、长度或 UART 错误时保存完整现场，先核查接线、输入电平与原始数据，再判断软件原因。没有实物操作记录时，帧解析主机测试只能证明解析与映射逻辑。
